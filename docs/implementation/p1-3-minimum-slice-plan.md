# P1-3 最小纵向切片准备

依据 D-02、AGENTS.md、开发指南 §3.6、§3.8、§5.3 P1-3 工作卡及其中 CAS 入库顺序。建议在本地 WSL 上交付账户／个人租户／项目 → 迁移与仓储 → 一种材料的不可变版本 → 当前委派下的受权精确查询。

## 契约与缺口

- [ownership.py](../../danus_ai/contracts/ownership.py) 的三种权威记录、归属修订与待认领边界已限定签收。[messages.py](../../danus_ai/contracts/messages.py) 已有精确引用查询、委派、签发归属快照、租约和用途复验。现有查询结果仅回显授权后的定位，切片若返回受限正文，需要一个明确的正文 DTO 或本地命令结果合同，以及正文读取前的同一授权快照守卫。
- 建议只用已批准投影的 CandidateHypothesis 工作材料，经已有 CandidateDraft／CandidateRecord 及 content_version 验证。使用具备精确来源准入的合成夹具。必须先固定目标版本、服务写入者、允许的材料字段和读取结果，核对已有投影的所有依赖能通过受限端口解析。若所选夹具需要额外材料合同，先补必要来源定位，或由 A0 改选一个已批准版本的目标。CAS 字节摘要仅核验制品完整性，科学版本沿用已有投影。
- 切片只含明确归属的私有材料，测试身份由受控服务夹具装配。未认领记录保持隔离。完整 R04 只读论断查询、R13 写入、显式认领工作流、搜索、真实身份签发、outbox 投递与通用材料迁移仍在 P1-3 后续范围。无消息消费者时，不把切片当作 outbox 投递验收。

## 实现与验收

1. 提交带版本号的迁移、模式说明和初始化命令。每个连接启用外键，验证 WAL 与实际 SQLite 版本。项目和材料使用复合租户／项目键，材料版本外键保留归属，版本唯一约束含类型、材料 ID 和精确版本。若引用跨归属，数据库约束及服务均拒绝。测试两租户及一个租户下两个项目。
2. 事务内提交归属关系、材料版本与制品元数据。CAS 字节先在同文件系统暂存并核对摘要，原子发布后才写元数据。失败不得留下成功响应、孤立业务行或不可读的有效引用。未引用制品经引用复核后延迟清理。相同归属、同版本、同字节可幂等，冲突版本拒绝，旧版本仍可精确读取。复核重复提交和双写竞争。
3. 用受信上下文核验当前账户、租户、项目、用途、委派、租约和目标修订，再按复合键查找并打开制品。授权失败不读文件、不泄露存在性。两租户同 ID／同哈希可独立保存，越权不得访问另一侧正文。覆盖错版本、同租户错项目、撤销、旧归属修订、原始制品路径旁路及损坏字节。验收以实际存取和拒绝行为为证。
4. 演练从测试快照恢复到独立目录。验证 SQLite integrity_check、foreign_key_check、迁移版本、制品摘要、当前权限及隔离。记录从快照截止点到恢复之间的风险；缺恢复后撤销来源时保持关闭受权查询。

## 启动条件与工时

D-02 的 SQLite/WAL 及 WSL/ext4 直接沿用。开始切片实现前，需独立授权、确认单一可用材料及正文读合同、确认受控写入与测试身份边界，以及核实实际文件系统、路径、UID、权限和备份空间。数据库创建必须由新授权明确区分测试环境与运行环境。建议先授权测试路径；运行库启用仍需恢复演练及运行范围确认。预算、真实发送与后续科研决定不属于该切片前置。

初估工程工时 12–20 小时。按 3–5 小时迁移与复合外键，3–5 小时版本写入和 CAS，4–6 小时受权查询、隔离及故障用例，2–4 小时恢复演练和证据整理估算。假定单类型、单进程、本地测试且无新依赖；若正文合同、并发策略或存储现场与假定不符，重新估算。
