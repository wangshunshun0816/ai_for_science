报告接收先校验双方定位、项目、决定和可读元数据，再读取受信端口中的精确修订正文并逐对象核对。运行与提交的两个 Scope 引用均校验当前读取权限与精确版本。固定四题 Scope 与运行不符时，提交准入继续拒绝，报告接收只允许与精确提交绑定且 G0 明确失败的拒绝报告。接受仍要求既有三关通过、全部运行有有效观测及可读论断引用。出现错误的关口不能作为科学拒绝，混合终因继续阻断。

清单执行器直接读取原件，按显式适配连接旧运行别名、尝试定位、协议、预注册、Scope 和原提交模板，逐行消费观测。两臂使用精确运行与尝试定位并登记当前可读事实。终态报告用受信测试端口模拟已经定位的关口与报告正文。测试适配器中的关口事实和锁定阈值仅用于固定四题契约验证。[正式守卫](../../danus_ai/contracts/submission.py) · [原件适配](../../tests/contracts/fixed_submission_path.py) · [清单执行](../../tests/contracts/test_exit_coverage.py)
